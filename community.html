工具

同时开一堆 agent，人的注意力撑得住吗？

科研品味要求超出模型能力时，人就得盯着，没法多线并行

有人多开几个进程就脑子痛苦；另一人认为科研品味要求超出模型能力，只能把简单任务丢后台。也有人实测两个任务并行加手写记录效率最高。有人怀疑十几个 agent 跑同一任务没用，另一人只批量跑补实验。

讨论小结

各人上限不同，多个 agent 跑同一任务有没有收益没有结论。

Eval

各家报告的 agent 分数，能复现吗？

很多公开分数，连怎么跑出来的都不清楚

复现 TB2 需对齐 timeout、资源和 token 上限，BrowseComp 只能从 tech report 扒 prompt。有人说自家 harness 塞 skill 刷分，上第三方榜就露馅。

讨论小结

有人提出可整理开源一批与 blog 分数一致的轨迹。

这则讨论的链接
Coding Agent

有了 AI，一个人维护大项目的核心可行吗？

一个人配 Agent 维护大项目，项目得完备到换个人也能指挥 Agent 接手

支持者以 FSDP2 为例，看重沟通少、能守住设计。另一方担心关键知识只在一个人和外部 Agent 手里，代码资产会脱离组织制度，交接和长期维护都有风险。回应者认为，项目要完备到不用原作者讲解，别人也能指挥 Agent 接手。

讨论小结

回应者给出了接手条件；这能否打消对组织稳定性的担忧，讨论里没有下文。
