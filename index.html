Eval摘录 / 01

模型不说人话，偏好数据和 benchmark 能捕捉到吗？

“

偏好标注只问更喜欢哪个，不问为什么，表达上的问题就漏掉了

讨论小结

内容准确和表达清楚怎样分开评，提示补丁能否在不同模型上稳定生效，都没有答案。

交流摘录

用户可能因为答案准确才选它，并不代表认可它的表达。过度发散、动不动认错、自造词，也很难写进 rubric。补救办法有禁词表、正负样本、在 skill 里写思路原则、用 persona 约束语气。也有人追问，强推理的表达和自然感是不是本来就冲突。

Data摘录 / 02

筛合成数据时，删掉错题就算高质量了吗？

“

合成数据的上限常被管线设计者的认知卡住，硬蒸馏前沿模型容易变成刷榜

讨论小结

几种做法可以互补；没有完美 oracle 时，专家判断怎样保证可靠仍是开放问题。

交流摘录

有人建议先抽样 rollout，归纳任务或 verifier 的错误，再到全集里删改；也有研究按学习信号信噪比动态删掉有害样本。工业界的人提醒，前提是题目本身没错。垂域数据每题都要专家检查，一周只能回流几十题。

Eval摘录 / 03

代码重构 benchmark 分数极低，难在哪？

“

有人建议用真实 workload 评估重构，但很多写操作的流量回放不了

讨论小结

难点在验证本身；写操作流量能不能回放，还没有解决办法。

交流摘录

一个 SWE refactor 基准的 pass@1 只有 5.4%，验证靠 LLM as judge，加上测试用例和 no-op 检测。有人质疑 judge 是否可靠：rubric 写得不细就判不准，到底有没有改坏，还得靠完备的测试。做过项目重构的人建议录制流量、保存数据 snapshot，另一人指出很多写操作的流量回放不了。

摘自社群交流，保留讨论中的不同观点。
